kni-cascade is a shared CSS foundation for building responsive websites. It gives every project a familiar folder structure, so developers know where settings, base styles, components, and page styles belong.

At its core is a scaling system that preserves the relationships between typography, spacing, and dimensions as the viewport changes. It helps carry a design across screen sizes with less repetitive adjustment and fewer media queries.

Alongside that system are the foundations projects repeatedly need: typography, buttons, forms, layout helpers, and visual effects. Use what helps, leave out what doesn’t, and build on top of it.

kni-cascade is a starting point you own. Customize the defaults, extend what’s useful, and change what the project needs. It should help you build your design, never limit what you can do.

Getting started

KNI’s WordPress, Eleventy, and Next.js boilerplates seed your project’s scss directory with the latest version of kni-cascade during setup. From there, those files belong to your project—customize them freely. Existing projects don’t automatically receive future kni-cascade updates.

Configuration

Before building pages, set the project’s typography, scaling, and component defaults to match the Figma design. The settings below show where to make those changes.

Typography
Match $type-scale in scss/00-sass/_variables.scss to the desktop and mobile typography variables in Figma.
Scaling
Check the mobile and desktop reference dimensions in scss/01-base/_scaling.scss. They default to 390px and 1440px wide.
Components
Set shared appearance and sizing once, then extend each component as needed. For buttons, use $btn-design and $btn-sizes.
Only what you need
Comment out unused forwards in the components and utilities entry files, then rebuild to omit their CSS.

Scaling

kni-cascade uses a shared scale to keep dimensions, spacing, and typography in proportion as the viewport changes.

Open the interactive scaling demo to resize a sample site and explore squish, reference proportions, the height floor, and scaling limits. The demo starts at 75% squish to make the effect easier to explore; the library default is 100%.

postcss-pxv

Think of pxv as a design-reference pixel. Write the size from your design, and kni-cascade scales it using the viewport and the active mobile or desktop settings.

You write

.card {
  padding: 24pxv;
}

PostCSS outputs

.card {
  padding: calc(24 * var(--pxv-unit));
}

Browser computes

One shared unit keeps every pxv value in proportion. The browser calculates the final size as the viewport changes. Here’s what that padding becomes at a few desktop widths:

Computed padding using the default 1440px desktop reference width, with enough viewport height for width to determine the scale

1440px (desktop basis)24px
1600px26.67px

Values are rounded to two decimal places. Standard px values stay fixed.

When to use pxv

Basically always! If you find yourself reaching for px, you probably want pxv. Use fixed pixels for details that should stay a consistent thickness or size, such as borders, dividers, outlines, and small optical adjustments. Typography applies minimum font-size clamps for readability.

Breakpoints

One simple media query

One simple media query switches the site-basis settings that power scaling in kni-cascade. The site starts with its mobile basis settings, including a reference width of 390px. At $tm (768px by default), the query activates the desktop basis settings, including a reference width of 1440px. Typography switches between its mobile and desktop sizes at the same threshold by default.

That media query switches the design basis; pxv handles the sizes in between. Spacing, dimensions, and other pxv values scale together as the viewport changes, while typography follows its configured scaling and readability limits. Instead of repeatedly adjusting individual values across tablet, laptop, and desktop widths, you define the mobile and desktop compositions and let the shared scaling system carry them through each range.

Use @include sm and @include lg for structural changes at that same switch. With the defaults, sm applies below 768px and lg applies from 768px upward. For example, stack a feature on mobile and place its image and text side by side on desktop:

.feature {
  display: grid;
  gap: 24pxv;

  // Mobile: stack the image and text.
  @include sm {
    grid-template-columns: 1fr;
  }

  // Desktop: show two equal columns.
  @include lg {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

The layout changes once, while the 24pxv gap scales within each range. Use the same mixins to change navigation or rearrange content, and add other media queries when the content needs them.

Advanced scaling settings

These defaults should work for most projects without adjustment. If you’re feeling ambitious, here’s what’s happening under the hood—and how to fine-tune the scaling for your design.

Edit the mobile and desktop CSS custom properties in scss/01-base/_scaling.scss; the primary media query activates the appropriate set.

Reference dimensions
--mobile-basis-w and --desktop-basis-w match the design widths: 390 and 1440 by default. Their height counterparts, --mobile-basis-h and --desktop-basis-h, default to 667 and 750. Reference height affects scaling only when squish is above zero. Enter these dimensions as unitless numbers.
Desktop squish
--desktop-squish defaults to 1. Normally, pxv scales from viewport width. When a desktop window is wide but short, width alone can make the composition too large for the available height. Squish lets the calculation switch to a viewport-height-based scale when that produces a smaller result. This helps a hero's typography, spacing, and imagery stay in proportion in a short laptop window.
How the switch works
At 1, the calculation uses whichever scale is smaller: viewport width relative to the reference width, or viewport height relative to the reference height. With the default desktop basis of 1440 × 750, a 1440 × 600 window produces a height-based scale of 0.8, so 100pxv becomes 80px. At 0, height has no influence and that same value stays 100px. Values between zero and one soften the height influence. Mobile defaults to width-only scaling.
Floor
--desktop-floor defaults to 500. Below that viewport height, the height calculation continues using 500px, preventing short windows from shrinking the composition indefinitely. This does not set a minimum page height. The mobile floor defaults to 0 and has no effect while mobile squish is zero.
Scaling limits
The active minimum and maximum clamp the scale to equivalent viewport widths. Mobile uses 0 through $tm - 1; desktop starts at $tm and caps at $desktop-max, which defaults to 1800. Set $desktop-max in scss/00-sass/_variables.scss to change that cap. Height influence can keep the scale below it. These limits constrain sizing without changing the layout breakpoint.

For example, reduce --desktop-squish if a wide, short window makes the composition feel too small. Raise --desktop-floor if you want the height-based shrinking to stop sooner. Use @include max for layout rules at and above $desktop-max.

[btn]

A shared starting point for consistent button sizing across projects. Make the appearance your own with project colors, spacing, hover effects, and animation. Extend [btn], or take just the sizing and build your own.

Make it yours

Set your project’s colors, corners, and spacing in scss/00-sass/_variables.scss. $btn-design controls appearance; $btn-sizes keeps responsive label sizes and padding together. Start with these defaults and adapt them to your design.

// Allow labels to grow beyond their configured mobile/desktop font sizes.
$btn-scale-up: false !default;

$btn-design: (
  radius: 999pxv,              // Corner radius; 999pxv creates a pill
  weight: 600,                 // Label font weight
  nudge: 0.01em,               // Optical vertical label adjustment
  gap: 0.5em,                  // Space between label and icon
  speed: 0.2s,                 // Color transition duration
  background: #001a3d,         // Default background and outline color
  text: #fff,                  // Default label color
  hover-background: #123456,   // Hover and pressed background
  hover-text: #fff,            // Hover and pressed label color
  focus: #0061c7               // Keyboard focus ring
) !default;

Adjust horizontal and vertical padding for each size separately. Height follows the label, line-height, and padding; no fixed or minimum button height is applied.

// padding-x = left/right; padding-y = top/bottom. Both follow the label size.
$btn-sizes: (
  xs: (desktop: 11, mobile: 10, padding-x: 1.5em, padding-y: 0.5em),
  s: (desktop: 12, mobile: 11, padding-x: 1.5em, padding-y: 0.625em),
  m: (desktop: 14, mobile: 12, padding-x: 1.5em, padding-y: 0.75em),
  l: (desktop: 16, mobile: 14, padding-x: 1.5em, padding-y: 0.75em)
) !default;

Usage

Bare btn defaults to medium. Add size and treatment tokens as needed.

<button type="button" btn="s">Small action</button>

Sizes

Use xs, s, m, or l. Each size controls typography and padding together. Labels use the desktop and mobile values in $btn-sizes, using the global --font-min-clamp minimum (12px in this demo). Button tokens start one step below their corresponding body tokens. The global minimum can make the smallest labels render at the same size; their padding still differs. By default, labels scale down but stop growing at their active mobile or desktop reference size. Set $btn-scale-up: true in settings to allow upward scaling.

Utilities

kni-cascade ships with helpful utility classes for layout, alignment, and visibility, plus visual effects such as shadows, scrims, and animated inset borders. Use them to handle common styling tasks while keeping your project's design and component structure your own.

Apply layout helpers through classes, such as <div class="flex j-sb a-c">...</div>. Add visual effects to individual elements with attributes, or use their Sass mixins to build the same treatment into a component class. Both approaches share the same implementation; choose whichever fits the way you're building.

Only include what you need. In your project's copy of scss/01-base/utilities/_index.scss, comment out unused utilities and rebuild to remove their CSS from the output:

@forward 'dev';
@forward 'display';
@forward 'flex';
@forward 'spacing';
// @forward 'scrim';
// @forward 'shadow';
// @forward 'inset-border';

Visual effects use custom HTML attributes alongside your component classes. CSS attribute selectors match these attributes and their space-separated options, keeping each effect's settings together in your markup.

This card gets a shadow with elevation 20 and intensity .1:

<div class="news-card" shadow="20 .1">Card content</div>

This image gets a scrim that fades toward the top, with .5 opacity and a 75% fade distance:

<figure class="hero-image" scrim="to-t .5 75%">
  <img src="photo.jpg" alt="Mountain landscape">
</figure>

Your component class still controls the rest of its design. If every instance needs the same effect, use its Sass mixin in the component class instead. Mixins remain available through scss/00-sass even when their attribute utilities are omitted.

[shadow]

Explore the shadow CodePen

Combine elevation, intensity, and an optional color. Options can appear in any order.

<div shadow="20 .1 blue">A low blue shadow</div>
Elevation
10, 20, 30, 40, or 50, from a tight shadow to a broad, lifted shadow. These are preset names, not pixel measurements.
Intensity
.1 through .9, from lighter to darker. This sets the base opacity; individual shadow layers also apply weights, so it is not the final combined opacity.
Color
black by default. Add blue for the blue preset, or set style="--shadow-color: 120, 40, 90;" for a custom RGB color.
Hover only
use shadow-hover="30 .1". It also activates on keyboard focus for buttons and links.
Resting and hover
combine shadow="20 .1" with shadow-hover="50 .2". Hover settings override only the options supplied; omitted options retain the resting values.

Use shadow for a persistent shadow. Elevation presets run from 10 (tight) to 50 (broad). Bare shadow defaults to elevation 30 with intensity 0.08.

These buttons already have a shadow. Hover or Tab to them to change elevation, intensity, and optionally color; move away to restore the resting settings.

Build shadows into a component

Use attributes for individual elements, or include the same styling in a component class. Import scss/00-sass for mixins without generating utility CSS. Omitted hover arguments retain the resting settings.

@use '../scss/00-sass' as *;

.mixin-shadow-card {
  @include shadow(20, 0.1);
  @include shadow-hover(30, 0.2);
}

.mixin-shadow-hover {
  @include shadow-hover(20, 0.2, (0, 20, 190));
}

[scrim]

A scrim is a gradient overlay that darkens part of an image and fades to transparent. Use it behind text on photos, hero images, or cards to improve readability while keeping the image visible. Choose a direction that puts the darkest area behind your text, and check contrast against the actual image.

Scrims use an eased, multi-stop gradient for a more gradual fade into the image than a standard two-stop gradient. Learn more in Easing Linear Gradients on CSS-Tricks.

Build a scrim into a component

When every image in a component needs the same treatment, include scrim() on its class instead of repeating the attribute. Arguments are direction, opacity, fade distance, and an optional RGB channel list. The effect reserves ::before.

One class, shared treatment

class="mixin-scrim-image" — no scrim attribute

@use '../scss/00-sass' as *;

.mixin-scrim-image {
  @include scrim(to-t, 0.6, 75%, (0, 20, 72));
}

[inset-border]

An inset border grows inward on hover or keyboard focus, over images and other content without changing layout. Use the attribute on individual elements or the mixin on a component class. The effect is invisible at rest.

Attribute on an image card inset-border
@include inset-border(5pxv, #a5106f);
inset-border disabled 
<a class="news-card" inset-border href="/story">Read the story</a>

Set color, thickness, and duration on your component class. Defaults are currentColor, 5pxv, and 350ms. The overlay inherits the element's corner radius.

.news-card {
  border-radius: 12pxv;
  --inset-border-color: #2a649c;
  --inset-border-width: 5pxv;
  --inset-border-speed: 350ms;
}

Build it into a component

@use '../scss/00-sass' as *;

.news-card {
  @include inset-border(5pxv, #2a649c, 350ms);
  border-radius: 12pxv;
}

The effect reserves ::after and sets position: relative. Set your own positioning after the mixin or override the attribute rule if the host needs absolute, fixed, or sticky positioning. Use a block or inline-block host. The overlay ignores pointer events, preserves the host's own shadow, and disables its transition for reduced motion. Keep an accessible focus indicator; this decorative effect does not replace it.

To omit the attribute CSS, comment out @forward 'inset-border'; in scss/01-base/utilities/_index.scss. The mixin remains available through 00-sass.

Images & positioning

Image fitting

Give the frame a height or aspect ratio, then choose how the image fills it.

Cover

Fill the frame; crop the edges.

Contain

Show the whole image; leave space as needed.

<figure class="fit-photo cover" style="aspect-ratio: 16 / 9;">
  <img src="photo.jpg" alt="Describe the image">
</figure>

Use .fit-photo.contain instead of .fit-photo.cover to preserve the entire image. Both work with direct child images and videos.

Clipping

A decorative layer clipped to its wrapper, with a fixed, viewport-height inner layer.

<div class="clip-container">

</div>

The wrapper disables pointer events. Keep interactive content outside it.
